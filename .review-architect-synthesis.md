- MEDIUM: `coldLoadStoppedMember` vs `doColdLoad` vs `KickColdLoad` — three layers of cold-load with similar names, hierarchy invisible.

- BEST COMMENT highlighted: `coldLoadMu` struct field docstring (`admission.go:64-79`).

## Architect 2: Test Design (`a893bb82`)

**Brittle tests**:

- Already-broken: the redeploy_test.go:399 assertion noted above.

**Flaky-test suspects**:

## Architect 3: API Contract (`a348aef7`)

**Verdict**: minor polish (fundamentals sound, no API structurally broken).

**Top findings**:
1. **CRITICAL**: `AdmissionEvictor` interface source-breaking — `StopForEviction` added with no optional-interface escape hatch. Any external implementer fails to compile.
2. **CRITICAL**: `Router` interface source-breaking — `IsModelColdLoading` + `KickColdLoad` added the same way. The test infrastructure already shows the pain (stubCoord had to add stubs).

**Important findings**:
- `/admin/redeploy-member` returns three different JSON shapes depending on path (success/failure-with-result/pre-flight-error).
- `warming_up` (OpenAI) vs `overloaded_error` (Anthropic) — semantically different to a client polling, even though they trigger on the same condition.
- `NotifySleep(name)` → `NotifySleep(name, reason)` signature change.
- `redeployDockerCmd` is package-level not Scheduler-field — multi-Scheduler-per-process tests cross-contaminate.
- `host:` field does dual duty (DNS hostname + docker container name) — fragile when compose project prefixes service names.
- Validator missing: solo-member swap_group with `evict_action: stop` is silently accepted (semantically broken).
- Stale `LifecycleColdLoad` comment claims "Not emitted yet" but is.
- `SleepsTotal{reason="stop:..."}` compat shim pollutes the counter; just remove (no external dashboards).
- vLLM API version pinning is implicit — no startup probe, no defensive parsing.

**Names architect would change**:
- `IsModelColdLoading` → `IsModelColdStartPending`
- `KickColdLoad` → `TriggerColdStart`
- `WithColdLoadLock` → `WithColdStartLock`
- `redeployDockerCmd` → `Scheduler.dockerCmd` field
- `ErrRedeployIneligible` → `ErrRedeployNotEligible`
- `admissionReason` (const) → `evictReasonAdmission`

## Cross-cutting Real Bugs (consensus)

These appeared in 2+ reviews and are concrete bugs/gaps:

1. **Test passes vacuously** (test-design + would have been API/maintainability if they'd traced it): `TestRedeployMember_SwapGroupOnlyIneligible` assertion mismatches production error string. **Concrete fix**: change assertion to use `errors.Is(err, ErrRedeployIneligible)` or check against the actual format.

2. **Public interface source-breaking changes** (API + maintainer): `AdmissionEvictor` and `Router`. **Concrete fix**: split into optional interfaces, type-assert at callsite.

3. **`IsTracked`/`TrackedModels` zero coverage** (test-design): trivially testable. **Concrete fix**: 4-line tests in admission_test.go.

4. **Wake-failure budget leak path untested** (test-design): genuine risk. **Concrete fix**: integration test that injects vLLM /wake_up 500.

5. **Documentation gaps** (maintainer): README/CLAUDE.md/spec.md don't mention tonight's new fields. **Concrete fix**: 1 commit updating docs (the user has explicitly rejected HANDOFF.md but README/spec are source-of-truth files, NOT runbooks).

6. **`stop:`-prefixed reasons in SleepsTotal** (API) is now redundant given `StopsTotal` exists. **Concrete fix**: remove the duplicate increment.
